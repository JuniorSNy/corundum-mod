## 复现与 runner 修复

未修改 RTL 时，QP 256 case 的仿真在约 10408 ns 给出 PASS，pytest 却没有退出。
30/60 秒诊断截止会触发 cocotb-test 0.2.4 的异常终止路径：
`AttributeError: 'StreamReader' object has no attribute 'flush'`，不能把此结果算通过。
同一 pytest 进程运行 QP 256/512 时，也曾在第二个 case 的编译进程等待阶段挂住。

调用栈停在 `Simulator.execute → asyncio.run → selector.select`。
独立最小复现只循环启动 `/usr/bin/true`，使用 asyncio PIPE/communicate，第二次就可能停住；
诊断时子进程已经消失，主线程仍等待 selector。同步 subprocess 对照连续 100 次通过。
这定位到当前 Python 3.10 执行环境的 asyncio 子进程退出通知/等待路径，
没有进一步归因到某个 CPython 上游缺陷或 sandbox 实现。

`tb/runner_diagnostic.py` 提供有截止的独立复现（不需要 RTL）：

```bash
python tb/runner_diagnostic.py --backend async
python tb/runner_diagnostic.py --backend sync
```

async 挂起时诊断返回非零；未复现时正常退出，不将偶发性掩盖为确定发生。
新的 `sim_runner.py` 复用 Icarus source/parameter/env 配置，以同步 Popen/wait 和文件日志执行进程。
超时会终止进程组并失败，信号处理会恢复；必须取得正常进程退出及预期数量的非空、无失败/跳过 XML。
每次重新编译，避免 cocotb-test 的时间戳缓存漏掉参数变化。
`test_sim_runner.py` 用真实 Icarus/cocotb 运行验证正常、故意失败、skip、无测试四种结果。

## 已实施的重构

- 按 `tb/raw_mr_table`、`tb/raw_packet_qp`、`tb/mqnic_core_pcie_us`、`tb/fpga_core` 分目录，提供 Makefile/pytest 入口。
  统一 runner 在一个 pytest 进程运行，故意覆盖多次启动/退出。
- 集成配置永久包含 1×1、1×2、2×1，DDR/HBM 均关闭；每个普通端口均 TX/RX，raw 固定 port 0。
  scoreboard 分别检查每个 normal 流和 raw 流的内容与顺序，不限制不同流之间的仲裁顺序。
- CQ 按 commit sequence 有截止地轮询，不依赖固定 1000 ns 等待或仅依赖 CSR producer。
  QP 主机模型故意让 DMA status 先于最后 DWORD 100 ns 发布，验证软件等待协议。
- 增加 app-enabled Alveo `fpga_core` 2×1 变体，直接复用原 Verilog 顶层、TB 和参数/source 配置，
  运行 raw 场景以及原 `run_test_nic` 全部断言。Scapy 只用于离线序列化，导入时屏蔽主机路由枚举。
  原板级测试的 APP_ENABLE=0 路径没有修改。
- 抽出 `raw_packet_csr.v`，拥有 host doorbell、配置寄存器、MR staging；QP 保留硬件消费者与 CQ producer 所有权。
  CSR bank 支持默认值为零的 RB_BASE_ADDR/RB_NEXT_PTR，app 仍采用原零偏移布局；非零重定位尚无独立覆盖。
- QP 和 raw DMA 状态更新改为保持默认值的 `*_reg/*_next`，保持同步高有效复位、接口和单在途行为。
  命名 CSR offsets、SQE 字段、DMA tags、CQ status 和 raw port/tag 约定。
  C 头文件与辅助驱动使用命名寄存器常量，未改变 ioctl 或资源回收语义。
- 增加等待 MAC completion 时 stop/drain、SQ DMA 错误后继续工作、CQ fatal 清错后重启发包场景。
  原有 MR、payload 错误、反压、CQ 满和绕环断言保留。
